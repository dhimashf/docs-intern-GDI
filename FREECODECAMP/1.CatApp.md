# 1. Basic HTML Document

Struktur paling dasar yang digunakan:

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>CatPhotoApp</title>
  </head>

  <body>
    ...
  </body>
</html>
```

### `<!DOCTYPE html>`

Deklarasi bahwa dokumen menggunakan HTML5.

Ini bukan HTML element, tetapi **doctype declaration** yang dibaca browser sebelum memproses dokumen.

### `<html>`

Root element dari seluruh dokumen HTML.

```html
<html lang="en">
```

`lang="en"` merupakan attribute yang memberi informasi bahwa bahasa utama dokumen adalah English.

Attribute tidak berdiri sebagai element baru. Attribute memberikan **informasi tambahan atau konfigurasi** kepada element.

### `<head>`

Berisi metadata dan informasi tentang dokumen yang tidak menjadi konten utama halaman.

Contohnya:

```html
<head>
  <meta charset="utf-8">
  <title>CatPhotoApp</title>
</head>
```

### `<meta charset="utf-8">`

Menentukan character encoding yang digunakan dokumen.

`meta` termasuk **void element**, sehingga tidak memiliki closing tag.

### `<title>`

Menentukan judul dokumen yang muncul pada browser tab.

`title` berada di dalam `head`, bukan `body`, karena title merupakan informasi tentang dokumen, bukan konten halaman yang ditampilkan.

### `<body>`

Berisi konten utama yang dirender pada halaman.

Struktur sederhananya:

```text
html
├── head
│   ├── meta
│   └── title
│
└── body
    └── visible content
```

# 2. Semantic HTML

Di dalam `body`, struktur CatPhotoApp menggunakan:

```html
<body>
  <main>
    <section>
      ...
    </section>

    <section>
      ...
    </section>

    <section>
      ...
    </section>
  </main>

  <footer>
    ...
  </footer>
</body>
```

Element seperti `main`, `section`, dan `footer` termasuk **semantic HTML elements**.

Semantic HTML berarti element dipilih berdasarkan **makna atau perannya**, bukan hanya bentuk visualnya.

Contohnya:

```html
<section>
  <h2>Cat Photos</h2>
  ...
</section>
```

`section` memberi informasi bahwa content di dalamnya merupakan satu bagian/topik tertentu.

Berbeda dengan:

```html
<div>
  <h2>Cat Photos</h2>
  ...
</div>
```

`div` hanya merupakan generic container. Browser tidak mendapatkan informasi khusus mengenai makna bagian tersebut.

### Insight

Semantic HTML pada dasarnya membuat struktur halaman lebih mudah dipahami oleh:

* developer
* browser
* assistive technology
* search engine

Jadi semantic HTML bukan berarti "tag yang tampilannya bagus", tetapi **tag yang menjelaskan peran content**.

# 3. `<main>`

```html
<main>
  ...
</main>
```

`main` merupakan **semantic element** yang menandai konten utama dari halaman.

Pada CatPhotoApp, tiga bagian utama berada di dalam `main`:

```text
main
├── Cat Photos
├── Cat Lists
└── Cat Form
```

`main` bukan sekadar container pengganti `div`.

Element ini memberikan informasi bahwa content di dalamnya merupakan **primary content** halaman.

# 4. `<section>`

```html
<section>
  <h2>Cat Photos</h2>
  ...
</section>
```

`section` juga merupakan **semantic element**.

Fungsinya mengelompokkan content yang mempunyai tema atau bagian yang sama.

Pada CatPhotoApp:

```text
main
│
├── section → Cat Photos
├── section → Cat Lists
└── section → Cat Form
```

Biasanya sebuah `section` memiliki heading yang menjelaskan topiknya.

Karena itu struktur:

```html
<section>
  <h2>Cat Photos</h2>
  ...
</section>
```

lebih bermakna daripada sekadar:

```html
<div>
  ...
</div>
```

### Insight

`section` bukan berarti "setiap kotak di halaman".

Pertimbangannya adalah:

> Apakah content ini merupakan satu bagian/topik yang dapat diberi judul?

Kalau iya, `section` masuk akal.

# 5. `<footer>`

```html
<footer>
  <p>
    No Copyright -
    <a href="https://www.freecodecamp.org">freeCodeCamp.org</a>
  </p>
</footer>
```

`footer` termasuk **semantic element**.

Digunakan untuk informasi penutup dari sebuah page atau section.

`footer` tidak harus selalu berarti "bagian paling bawah secara visual". Maknanya adalah **informasi penutup**.

Dalam CatPhotoApp, footer berada di akhir `body`, sehingga sekaligus menjadi bagian paling bawah halaman.

# 6. Heading Hierarchy

```html
<h1>CatPhotoApp</h1>

<h2>Cat Photos</h2>
<h2>Cat Lists</h2>
<h2>Cat Form</h2>

<h3>Things cats love:</h3>
<h3>Top 3 things cats hate:</h3>
```

Heading juga merupakan bagian dari struktur semantic dokumen.

Hierarchy-nya:

```text
h1 — CatPhotoApp
│
├── h2 — Cat Photos
│
├── h2 — Cat Lists
│   ├── h3 — Things cats love
│   └── h3 — Top 3 things cats hate
│
└── h2 — Cat Form
```

`h1` menunjukkan topik utama.

`h2` menunjukkan bagian utama.

`h3` menunjukkan subbagian dari `h2`.

### Insight

`h1` sampai `h6` bukan sekadar ukuran font.

Ukuran visual nantinya dapat diubah menggunakan CSS.

Heading lebih penting dilihat sebagai **hierarchy informasi**.

# 7. `<p>` — Paragraph

```html
<p>
  Everyone loves
  <a href="...">cute cats</a>
  online!
</p>
```

`p` merupakan semantic element untuk paragraph.

Element ini juga menunjukkan bahwa HTML memiliki struktur bertingkat.

```text
p
└── a
```

`p` menjadi parent dari `a`.

Hubungan seperti ini disebut **nesting**.

Nesting membentuk struktur DOM yang nantinya akan digunakan browser untuk memahami hubungan antar-element.

---

# 8. `<a>` — Anchor / Link

```html
<a href="https://freecatphotoapp.com">
  cat photos
</a>
```

`a` adalah **anchor element**, digunakan untuk membuat hyperlink.

`href` menentukan destination.

```text
a
└── href → destination
```

`href` tidak hanya harus berupa URL halaman.

Pada kode CatPhotoApp, salah satu `href` langsung mengarah ke file gambar:

```html
<a href="https://cdn.freecodecamp.org/.../running-cats.jpg">
  cute cats
</a>
```

Artinya link dapat mengarah ke berbagai resource, bukan hanya halaman website.

---

# 9. `target="_blank"`

```html
<a
  target="_blank"
  href="https://freecatphotoapp.com"
>
  cat photos
</a>
```

`target` menentukan konteks tempat destination dibuka.

`_blank` meminta browser membuka link pada browsing context baru, biasanya tab baru.

Perbedaannya:

```text
href
→ ke mana link menuju

target
→ bagaimana/di mana destination dibuka
```

# 10. `<img>`

```html
<img
  src="https://cdn.freecodecamp.org/curriculum/cat-photo-app/relaxing-cat.jpg"
  alt="A cute orange cat lying on its back."
>
```

`img` digunakan untuk menampilkan gambar.

### `src`

Menentukan sumber atau lokasi file gambar.

### `alt`

Alternative text yang mendeskripsikan gambar.

`alt` penting ketika gambar tidak dapat ditampilkan dan juga menjadi informasi yang dapat digunakan oleh assistive technology.

### `img` sebagai void element

`img` tidak mempunyai content yang dibungkus di dalamnya, sehingga tidak memiliki closing tag.

Benar:

```html
<img src="..." alt="...">
```

Bukan:

```html
<img src="..." alt="..."></img>
```

### Insight

`img` membutuhkan `src` untuk **mengambil resource**, sedangkan `alt` memberikan **makna/deskripsi** terhadap resource tersebut.

---

# 11. `<img>` di dalam `<a>`

```html
<a href="https://freecatphotoapp.com">
  <img
    src="..."
    alt="A cute orange cat lying on its back."
  >
</a>
```

Strukturnya:

```text
a
└── img
```

Karena `img` menjadi child dari `a`, gambar tersebut menjadi bagian dari hyperlink.

Pattern ini sering digunakan ketika seluruh gambar ingin dijadikan clickable link.

# 12. `<ul>`, `<ol>`, dan `<li>`

### Unordered List

```html
<ul>
  <li>catnip</li>
  <li>laser pointers</li>
  <li>lasagna</li>
</ul>
```

`ul` = unordered list.

Digunakan ketika urutan item tidak memiliki makna.

### Ordered List

```html
<ol>
  <li>flea treatment</li>
  <li>thunder</li>
  <li>other cats</li>
</ol>
```

`ol` = ordered list.

Digunakan ketika urutan item memiliki makna.

### `li`

`li` = list item.

```text
ul / ol
├── li
├── li
└── li
```

### Insight

Perbedaan `ul` dan `ol` sebaiknya dipahami dari **makna data**, bukan hasil visualnya.

```text
ul → urutan tidak penting
ol → urutan penting
```

Kalau CSS nanti menghilangkan bullet atau mengubah tampilannya, semantic HTML-nya tetap sama.

```html
<figure>

  >

  <figcaption>
    Cats <em>love</em> lasagna.
  </figcaption>
```

`figure` merupakan **semantic element** untuk content yang dapat berdiri sebagai satu unit, misalnya:

* gambar
* diagram
* ilustrasi
* code snippet
* media tertentu

Dalam CatPhotoApp, gambar dan caption menjadi satu kesatuan.

```text
figure
├── img
└── figcaption
```

# 14. `<figcaption>`

```html
<figcaption>
  Cats <em>love</em> lasagna.
</figcaption>
```

`figcaption` adalah caption atau keterangan untuk content di dalam `figure`.

`figcaption` bukan sekadar `<p>` yang kebetulan berada di bawah gambar.

Element ini secara semantic menjelaskan:

> Teks ini merupakan caption dari figure.

Karena itu kombinasi:

```html
<figure>
  <img ...>
  <figcaption>...</figcaption>
</figure>
```

memiliki hubungan semantic yang lebih jelas dibandingkan menggunakan generic container.

---

# 15. `<em>`

```html
<em>love</em>
```

`em` berarti **emphasis**.

Digunakan ketika sebuah bagian teks mendapatkan penekanan.

Browser secara default biasanya menampilkannya dengan italic.

Namun italic bukan tujuan utama element ini.

```text
em
→ semantic meaning: emphasis
→ default visual: italic
```

CSS tetap dapat mengubah tampilannya.

---

# 16. `<strong>`

```html
<strong>hate</strong>
```

`strong` menunjukkan **strong importance**.

Browser secara default biasanya menampilkan teksnya dengan bold.

Tetapi sama seperti `em`, makna semantic lebih penting daripada tampilan default.

```text
strong
→ semantic meaning: strong importance
→ default visual: bold
```

Perbedaannya:

```text
em
→ penekanan

strong
→ tingkat kepentingan yang kuat
```

# Forms

# 17. `<form>`

```html
<form action="https://freecatphotoapp.com/submit-cat-photo">
  ...
</form>
```

`form` merupakan element untuk mengelompokkan **interactive controls** yang digunakan untuk mengumpulkan dan mengirim data user.

`form` termasuk bagian dari HTML yang berhubungan dengan **user input**, bukan sekadar container biasa.

`action` menentukan URL tujuan ketika form dikirim.

```text
user input
    ↓
form
    ↓
action
    ↓
server
```

---

# 18. `<fieldset>`

```html
<fieldset>
  <legend>
    Is your cat an indoor or outdoor cat?
  </legend>

  ...
</fieldset>
```

`fieldset` merupakan **semantic form element**.

Fungsinya mengelompokkan beberapa form control yang memiliki hubungan.

Pada CatPhotoApp terdapat dua kelompok:

```text
fieldset
├── Indoor / Outdoor

fieldset
├── Personality
```

Jadi `fieldset` bukan sekadar kotak visual di sekitar input.

Maknanya adalah:

> Beberapa control ini merupakan satu kelompok yang saling berkaitan.

Browser biasanya memberikan border default pada `fieldset`, tetapi border tersebut bukan alasan utama element ini digunakan.

---

# 19. `<legend>`

```html
<fieldset>
  <legend>
    Is your cat an indoor or outdoor cat?
  </legend>

  ...
</fieldset>
```

`legend` adalah **semantic element khusus untuk memberikan caption/label pada sebuah `fieldset`**.

Hubungannya:

```text
fieldset
└── legend → menjelaskan kelompok control
```

Pada kode:

```text
fieldset
│
├── legend
│   └── Is your cat an indoor or outdoor cat?
│
├── radio → Indoor
└── radio → Outdoor
```

Jadi `legend` bukan heading biasa seperti `h2`.

`h2` digunakan untuk hierarchy heading pada dokumen.

`legend` digunakan untuk **memberi nama/konteks pada satu kelompok form control**.

### Insight

`fieldset` dan `legend` merupakan pasangan yang saling berkaitan:

```text
fieldset
→ mengelompokkan control

legend
→ memberi nama/konteks kelompok tersebut
```

Keduanya termasuk semantic HTML dan sangat berguna untuk membuat struktur form lebih jelas, terutama bagi assistive technology.

# Radio Button

## 20. `type="radio"`

```html
<input
  id="indoor"
  type="radio"
  name="indoor-outdoor"
  value="indoor"
  checked
>

<input
  id="outdoor"
  type="radio"
  name="indoor-outdoor"
  value="outdoor"
>
```

Radio cocok untuk pilihan yang **saling eksklusif**.

Kunci grouping-nya ada pada:

```html
name="indoor-outdoor"
```

Karena kedua radio memiliki `name` yang sama, keduanya menjadi satu radio group.

```text
Indoor   ○
Outdoor  ○
```

Hanya satu pilihan yang dapat dipilih dalam group tersebut.

---

# 21. `name` pada Form Control

```html
name="indoor-outdoor"
```

`name` berfungsi sebagai **nama/key data form**.

Misalnya:

```html
<input
  type="radio"
  name="indoor-outdoor"
  value="indoor"
>
```

Jika dipilih, secara konsep datanya menjadi:

```text
indoor-outdoor=indoor
```

Jadi `name` mempunyai dua konteks penting pada form:

1. menjadi nama/key data yang dikirim
2. pada radio, `name` yang sama membuat control berada dalam satu group

---

# 22. `value`

```html
value="indoor"
```

`value` menentukan nilai yang akan dikirim ketika control tersebut dipilih.

Contoh:

```text
name="indoor-outdoor"
value="indoor"
```

menghasilkan:

```text
indoor-outdoor=indoor
```

Mental model form:

```text
name  → key
value → value
```

---

# 23. `checked`

```html
<input
  type="radio"
  ...
  checked
>
```

`checked` membuat radio atau checkbox sudah aktif ketika halaman pertama kali dimuat.

`checked` merupakan **boolean attribute**.

Kehadirannya berarti aktif.

```html
checked
```

tidak membutuhkan:

```html
checked="true"
```

# Checkbox

## 24. `type="checkbox"`

```html
<input
  id="loving"
  type="checkbox"
  name="personality"
  value="loving"
  checked
>
```

Checkbox digunakan ketika beberapa pilihan dapat dipilih sekaligus.

Pada CatPhotoApp:

```text
☑ Loving
☑ Lazy
☐ Energetic
```

Semua checkbox menggunakan:

```html
name="personality"
```

tetapi memiliki `value` yang berbeda.

Secara konsep:

```text
personality=loving
personality=lazy
personality=energetic
```

Radio dan checkbox sama-sama merupakan form control, tetapi model pemilihannya berbeda:

```text
radio
→ satu pilihan dalam group

checkbox
→ satu atau beberapa pilihan
```

# Label

## 25. `<label>`

Ada dua bentuk yang muncul di kode.

### Label membungkus input

```html
<label>
  <input
    id="indoor"
    type="radio"
    name="indoor-outdoor"
    value="indoor"
  >
  Indoor
</label>
```

Strukturnya:

```text
label
└── input
```

### Label dengan `for`

```html
<input id="loving" type="checkbox">

<label for="loving">
  Loving
</label>
```

Hubungannya:

```text
label[for="loving"]
        ↓
input[id="loving"]
```

Nilai `for` harus sama dengan `id` input.

### Insight

`label` bukan sekadar teks di samping input.

Label memberikan **nama/keterangan untuk form control** dan membuat hubungan antara teks dan input menjadi eksplisit.

Ini juga penting untuk usability dan accessibility karena user dapat berinteraksi dengan control melalui label.

```html
  type="text"
  name="catphotourl"

```

`type="text"` membuat control untuk input teks.

Attribute yang digunakan:

```text
type
→ jenis control

name

placeholder
→ hint

required

```

---

# 27. `placeholder`

```html
placeholder="cat photo URL"
```

Placeholder memberikan **petunjuk sementara** mengenai data yang diharapkan.

Placeholder bukan value.

```text
placeholder
→ "contoh/petunjuk apa yang perlu diisi"

value
→ data sebenarnya
```

Ketika user mulai mengetik, placeholder biasanya menghilang.

---

# 28. `required`

```html
<input
  type="text"
  name="catphotourl"
  required
>
```

`required` merupakan **constraint validation attribute**.

Artinya control tidak boleh kosong ketika form disubmit.

Alurnya:

```text
submit
  ↓
browser validation
  ↓
required field kosong?
  ├── ya → invalid
  └── tidak → lanjut
```

Ini termasuk **client-side validation** karena validasi dilakukan oleh browser sebelum request dikirim.

---

# 29. `<button type="submit">`

```html
<button type="submit">
  Submit
</button>
```

`button` merupakan interactive element.

`type="submit"` membuat button tersebut menjadi tombol untuk mengirim form.

Alur lengkapnya:

```text
User mengisi form
       ↓
Klik Submit
       ↓
Browser melakukan client-side validation
       ↓
Valid?
       ↓
Form dikirim ke action
```

# 30. Form Data

Dari beberapa attribute di atas, pola pengiriman data mulai terlihat:

```html
<input
  name="catphotourl"
  value="..."
>
```

Secara konsep:

```text
name=value
```

Misalnya user mengisi:

```text
https://example.com/cat.jpg
```

maka data secara sederhana dapat dipahami sebagai:

```text
catphotourl=https://example.com/cat.jpg
```

Untuk radio:

```text
indoor-outdoor=indoor
```

Untuk checkbox:

```text
personality=loving
```

Jadi `name` dan `value` bukan sekadar attribute untuk HTML. Keduanya berkaitan langsung dengan **data yang dikirim oleh form**.

Dari task ini terlihat beberapa jenis element yang berbeda.

```text
main
section
footer
figure
figcaption
```

Element-element tersebut memberikan makna terhadap struktur content.

```text

strong
```

Memberikan makna terhadap bagian teks.

```text

```

# 32. Attribute vs Element

Task ini juga memperjelas perbedaan element dan attribute.

Element:

```html
<a>...</a>
<img>
<form>...</form>
```

Attribute:

```html
href="..."
src="..."
alt="..."
type="..."
name="..."
value="..."
```

Mental model:

```text
Element
→ apa/jenis content atau control-nya

Attribute
→ informasi tambahan atau konfigurasi element tersebut
```

Contoh:

```html
<input
  type="radio"
  name="indoor-outdoor"
  value="indoor"
>
```

```text
input
│
├── type  → jenis control
├── name  → nama/key data + grouping radio
└── value → nilai data
```

```text
    ├── fieldset
    ├── legend
    ├── label
    ├── input
    └── button
```

Pola berpikirnya mulai terlihat:

```text
Apa content-nya?
       ↓
Apa perannya?
       ↓
Pilih element semantic yang sesuai
       ↓
Gunakan attribute untuk konfigurasi/detail
       ↓
Bangun hubungan antar-element melalui nesting
```

Dengan pola ini, HTML tidak lagi terlihat seperti sekumpulan tag yang harus dihafalkan. Setiap element memiliki **peran, konteks, dan hubungan** dengan element lainnya.
